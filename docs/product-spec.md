# AI 论文阅读网站：首版产品与验收规范

状态：设计草案；配套静态原型已在 GitHub Pages 上线，没有真实识别能力。

## 已确定的最终交付形式

用户指定使用 GitHub Pages 项目网站。当前静态原型已部署到 `https://windviolett.github.io/paper-reader/`，源码仓库为 `windviolett/paper-reader`。不以自购域名作为交付前提，真实论文处理功能仍待开发。

最终交付包括可访问的 Pages 前端、独立部署并联通的论文处理后端、完整源码、部署说明和真实论文验收记录。用户从 Pages 网址完成上传、查看进度、阅读与核对原文、保存和导出；仅发布虚构样稿不构成最终交付。后端存储、运行与模型调用费用另行配置。

## 目标与默认读者

将一篇计算机／AI 论文转成中文结构化阅读报告，服务有计算机基础但不熟悉细分方向的读者。英文术语首次出现保留原名。默认输出速览与精读两个层次，以可核对、忠实和易读为优先级。

首版深度支持 AI 方法论文。理论、综述、数据集或系统论文应显示类型和支持范围；用户可改类型，但不能套用不适用的字段制造实验。论文方向为多标签，论文类型单独保存。未能可靠判定时进入待确认状态。

## 页面与主要交互

1. 上传页：单 PDF 上传；显示处理范围、文件保留规则和产品限制。初始设计上限 20 MB / 50 页，接入供应商时重新核对并配置。加密、损坏和超限文件在计费处理前拒绝并解释原因。扫描页需具备 OCR／视觉处理能力，否则明确提示无法覆盖。
2. 任务页：排队、解析、提取、生成、校验、完成、部分完成、失败。刷新后通过任务 ID 恢复；状态展示阶段，不能编造完成百分比。失败显示可理解的原因，支持重试；重复点击不创建重复任务。
3. 阅读页：标题和元信息 → 概览 → 问题 → 贡献 → 方法 → 实验 → 局限 → 复现线索。桌面目录与正文并列，按需打开原文；手机用报告／原文切换。
4. 来源交互：点击页码跳到原文件实际页序，显示对应摘录；仅在有真实坐标时画高亮框。印刷页码另存。正文、附录分别标记覆盖状态。未验证引用清晰标注。
5. 编辑与导出：修改报告后保存用户版本，不覆盖原始生成结果。Markdown 和打印 PDF 为第一批导出格式；保持来源信息和缺失提示。Word 可在闭环完成后补充。

## 阅读内容约定

- 概览建议 200–400 中文字，精读建议 1500–3000 字；按论文复杂度调整，不能为了凑字数虚构内容。
- 问题：任务、现有瓶颈、成立条件。
- 贡献：区分作者主张、实验支持与外部新颖性验证。首版不自动声称完成外部文献核查。
- 方法：输入输出、直觉、训练／推理、关键机制、必要公式。不存在或识别失败的公式不得补造。
- 实验：数据集与划分、对照、指标方向、单位、具体结果、可比设置、消融和已报告的不确定性。
- 局限：作者陈述与系统阅读思考分开，推测标为待验证。
- 复现：只整理已报告信息，缺失用“未报告”；链接仅来自原文或后续明确记录的查证。
- 术语：按理解当前论文所需解释，避免百科式展开。
- 不输出未经校准的“论文质量 95 分”等分数；不把模型自报置信度当作正确概率。

## 后端数据约定

报告先保存结构化事实与证据，再渲染给读者。建议最小实体：

| 实体 | 核心字段 |
| --- | --- |
| Document | id、owner_id、file_hash、storage_key、page_count、正文／附录覆盖范围 |
| Job | id、document_id、status、stage、attempt、error_code、usage、模板／模型版本 |
| Evidence | id、document_id、物理页序、印刷页码、章节、图表／公式编号、摘录、可选坐标、验证状态 |
| Claim | id、所属模块、内容、性质、evidence_ids、缺失／冲突状态 |
| ExperimentResult | 数据集、划分、方法、配置、指标、单位、方向、数值、不确定性、evidence_ids |
| Report | id、版本、概览、模块内容、claim_ids、来源映射、生成／修改时间 |

Claim 性质：`paper_statement`、`explanation`、`inference`、`derived_calculation`。系统计算需保存公式与输入事实 ID。关键原文事实需要来源；辅助解释不能伪装成原文结论。

缺失值统一为 null，并用状态区分：`not_reported`（已检查但原文未报告）、`not_applicable`、`unreadable`（读取失败）、`not_processed`、`conflicting`。原型的 `demo_unverified` 只用于演示，不进入正式报告。

## 处理流程与失败处理

1. 校验文件并建任务；文件私有存储，模型 Key 仅在服务端。
2. 解析章节、页序与图表；参考文献独立标记，不能把引用文献实验当作本论文发现。
3. 识别类型；按章节或页组提取事实，保持证据 ID 和原始页序。长文分块后合并并检查遗漏及冲突。
4. 生成各阅读模块，使用结构化输出约束字段；后端校验类型、枚举、数值和来源存在性。
5. 检查表格数值、比较条件和结论强度。第二次模型调用只能辅助检查，不能视为独立事实证明。
6. 完成或标记部分完成，保存结果版本及用量。限流与暂时性故障有限次重试，解析失败可重跑对应阶段。设置单任务调用上限，避免无限付费重试。

PDF 中的文字是待分析数据，不得改变系统规则、触发工具执行或决定外部请求目标。模型内容安全渲染。正式多人版本落实文件和任务的用户隔离及删除策略。

## 建议技术落地

前端采用可导出静态文件的实现，发布到 GitHub Pages 项目子路径；可以使用 React，若使用 Next.js 则必须采用静态导出，不能依赖其服务端路由或服务端渲染。后端 Python / FastAPI 单独部署；后台 Worker 处理耗时任务；数据库 PostgreSQL；私有对象存储保管 PDF。通过内部模型接口隔离供应商。先用真实样本比较原生 PDF 输入与文本／OCR 路线，再决定默认处理方式。

页面资源使用相对路径或正确的仓库 base path。首版使用单页加 hash 路由，避免刷新子路由产生 Pages 404。公开前端配置仅包含后端 HTTPS 地址；密钥和上传文件不能放入 Pages 发布产物。后端按前端 origin 配置 CORS，并独立实施用户认证与文件授权；CORS 不能代替权限控制。详情见 `deployment.md`。

当前阶段不需要向量数据库、跨论文搜索、推荐算法或多模型编排。模型版本、供应商价格和页数限制在接入阶段核实，本文不承诺成本或耗时。

## 首版验收

建立 20–30 篇真实样本，覆盖 NLP、视觉、多模态等方法论文，同时加入综述、理论、扫描、长附录和复杂表格作为边界样本。调试集与独立验收集分开；每篇人工标注关键研究问题、方法要点、实验行、局限及来源。以下是待实际样本确认的首轮验收目标，不是当前能力声明。

| 项目 | 判定方法／首轮目标 |
| --- | --- |
| 论文类型 | 独立集人工核对；准确率目标 ≥90%，同时报告各类型样本数与误判，模糊项允许待确认 |
| 关键数值 | 对报告中所有主要实验数值逐项核对；主要结论涉及的数字、单位、百分点必须全部正确 |
| 来源 | 主要贡献、方法和结果逐项核对；每个关键事实有定位，引用页确实包含支持内容；不以“有页码”代替正确性 |
| 覆盖 | 人工列出关键事实清单，提取召回率目标 ≥90%；全文覆盖状态不得误报 |
| 忠实性 | 不出现虚构实验、虚构作者／链接、因果强度升级或把推测写成事实；发现后阻止该版本作为通过样本 |
| 阅读质量 | 至少两位有计算机基础的读者，根据报告回答问题、方法、结果和边界四项；记录正确情况及误解原因 |
| 异常路径 | 加密、损坏、超限、限流、超时均有明确状态；刷新恢复，有限次重试，不出现“假完成” |
| 导出 | 网页与导出的结论、数值、来源及缺失提示一致；长表格和分页可读 |
| 成本与速度 | 每篇记录页数、调用数、Token、费用及总耗时；比较中位数和 P95，再制定产品预算 |

关键事实被证据反驳或读取范围不足时，报告进入“需核对／部分完成”，不能作为已验证的完整报告。人工修改不应抹除这些状态。
