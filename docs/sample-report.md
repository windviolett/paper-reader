## 快速概览

**研究什么？** 检索增强问答通常把检索到的若干段落交给语言模型。固定选择相同数量的段落，可能引入无关信息，也可能为复杂问题提供不足的证据。

**怎么做？** 示例方法先检索候选段落，再由证据选择器判断相关性，在上下文预算内选取段落，最后交给冻结的生成模型回答问题。

**发现什么？** 虚构实验中，相比固定选取 8 段的基线，该方法在两个示例数据集上使用更少的输入 Token，并取得更高的精确匹配分数。该结果只覆盖示例中的模型、数据和设置。

**注意什么？** 未报告端到端耗时；输入 Token 减少不能直接证明整个系统更快或更便宜。选择器自身也有计算成本。

## 1. 问题与动机

固定数量的检索结果不能适应不同问题的证据需求。本文示例关注的问题是：能否在受限的上下文预算内，减少无关段落，同时保留足以回答问题的证据？【示例来源 S1：第 2 页】

这一问题假设检索候选中存在可用证据。如果检索阶段完全没有找到答案依据，后续选择器无法凭空补齐信息。

## 2. 核心贡献

1. 作者主张：提出根据问题与候选段落动态选择证据的方法。【S2】
2. 作者主张：在示例问答设置中改善回答质量与输入长度之间的权衡。【S3】
3. 证据边界：当前实验不支持“在所有任务上更好”或“端到端一定更快”的结论。

贡献的新颖性在此仅复述作者主张；没有经过外部文献检索验证。

## 3. 方法详解

### 直觉

【辅助理解】可以把证据选择器理解为阅读前的材料筛选：把更可能有助于回答问题的段落留下。这个类比不表示选择器必然能识别所有必要证据。

### 输入、流程与输出

- 输入：一个问题和检索器返回的 20 个候选段落。
- 选择：选择器为问题—段落对评分，按相关性筛选，并遵守上下文 Token 预算。
- 生成：将问题与选中段落输入冻结的语言模型。
- 输出：自然语言答案。来源依据应另行保留，不能仅靠答案内容推断。

【示例来源 S2：第 3–4 页】

### 训练与推理

训练阶段用相关性标签训练选择器，生成模型保持冻结。推理阶段不更新参数，依次执行检索、选择和回答。示例材料未给出足够详细的标签构造规则。

## 4. 实验与证据

### 如何解读

在 QA-A 上，EM 增加 2.0 个百分点；输入 Token 减少约 33.3%。后者是依据表中数字进行的系统计算，公式为 `(2400 - 1600) / 2400`。QA-B 的相应变化为增加 1.0 个百分点、输入 Token 减少 25%。

示例设定使用相同检索器、生成模型和候选段落数。仍缺少随机种子、误差范围、显著性分析与端到端耗时，无法判断提升是否稳定，也不能据此计算完整成本。

### 消融与主张

示例 QA-A 中，移除学习式选择器、改用检索分数排序后，EM 为 40.5，完整方法为 42.0。【S4】这提示选择器可能有贡献；缺少重复实验时，不能确定该差异的稳定性。

## 术语辅助理解

- **RAG（检索增强生成）**：先检索相关材料，再把材料作为语言模型生成回答的上下文。
- **消融实验（Ablation）**：移除或替换某个组件，观察结果如何变化，以研究该组件的作用。
- **EM（Exact Match）**：按照评测协议判断预测答案是否与标准答案完全匹配；具体文本归一化规则应以论文为准。
